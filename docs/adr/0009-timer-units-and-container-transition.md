# ADR 0009：计时、计量单位与容器转场

## 状态

已采纳（1.7.2 后续迭代）。

## 背景

应用从固定「工时」扩展为可配置计量单位，并新增应用内计时。单位只应改变
显示，不改变 v4 数据契约；计时则必须在锁屏、切后台和跨日后仍可恢复。
“我的”页二级入口使用 `OpenContainer` 后暴露出默认 elevation 黑边、
交叉淡入文字重叠和容器中段直角等问题。

## 决策

- 计量单位只作为展示层标签；`WorkDayRecord.hours` 仍是 `double`，工资、
  备份、导出和金额计算口径不变。
- Bento 快捷录入按单位给出三档：前两档累加，最后一档替换当天总量。
- 日编辑器、年度统计、工资面板、CSV 与备份页全部跟随当前单位；
  小时仍使用「时薪」「元/时」，其它单位显示「单价」「元/章」等。
- 计时快照存于 `SharedPreferences`，只在开始、暂停、继续、结束时落盘；
  当前读数由开始时刻现算，不每秒写盘。
- Android 前台服务用 `SystemClock.elapsedRealtime` 独立走时；通知小图标
  使用单色矢量，Android 13+ 首次开始时请求通知权限。
- 前台服务每秒重发通知短文本，覆盖流体云/焦点通知等不识别 Chronometer
  的厂商通道；界面大按钮只负责开始、暂停与继续。
- 跨日计时不拆到两天，归属日期固定为开始计时那天；跨日后界面上显示
  「跨日」标记，结束仍写回原日期。已有计时不会被新日期的「开始」静默覆盖。
- 计时条只在所在 Tab 可见且正在运行时每秒刷新；隐藏 Tab 或暂停时取消
  ticker，避免后台无意义唤醒。
- 结束计时按当日剩余额度写入，绝不产生超过每日上限的记录；存档只读或
  已结算时不能结束写入，但可确认后放弃计时，避免状态永久悬挂。
- `OpenContainer` 统一 `closedElevation/openElevation = 0`，起点 20px
  圆角，使用 `fadeThrough` 防止旧行文字与新页内容叠在同一帧；减少动效
  时转场时长归零。

## 后果

- 切换单位不会迁移数据，也不会改变历史工资或备份兼容性。
- 计时可以跨日结束，但界面只在当前月首页露出；回到本月即可操作。
- 通知权限被拒绝时计时仍能运行，但不会显示抽屉通知；设置页会明确提示。
- 容器转场不再出现黑色矩形边或中段文字重叠。
