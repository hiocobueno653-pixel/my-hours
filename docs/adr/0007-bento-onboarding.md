# ADR 0007：Bento 首页、容错持久化与品牌启动转场

## 状态

已采纳（1.7.2）。

## 背景

1.7.1 的首页仍是纵向堆叠的今日卡、月汇总与日历，首屏信息密度低；启动页、欢迎页和首页之间也存在白闪、双重缓动与 Dock 突然出现的问题。同时，本地存档只要有一条坏记录就整库回退，备份导入也无法保留其余有效数据。

## 决策

### 首页与日历

- Flutter 首页使用 1+2 Bento：左侧今日大卡（状态、工时、快捷步进、今日账目），右侧上下两张月工时/月工资卡。
- React 首页保持同一信息层级，使用 `.work-bento` 网格；两端都不改变字段含义与写入口径。
- 日历格统一为三层：日期 + 结算点、工时胶囊、备注/日薪标识。未记录日期只显示 3px 淡点，不再显示短横线。
- 普通工时使用收入绿，高工时或已结算使用琥珀色；今天使用浅蓝渐变 + 白色描边 + 内高光。

### 持久化

- 本地主文件与备份导入改为“外层结构严格、列表条目容错”：坏条目跳过并计数，全部条目无效时才拒绝。
- 跳过数量必须通过启动 SnackBar 或导入确认文案告知用户，不能静默丢失。
- 普通编辑使用 300ms 合并写盘；导入、清空、重试、生命周期切换使用立即落盘。

### 启动与转场

- 首帧显示 `TimepageLoadingScreen`，数据准备完成后 280ms 淡出；最低展示 650ms，避免一闪而过。
- 加载记号的擦除动画周期 1900ms；减少动效时冻结在 0.95 的静态字标。
- 欢迎页到首页使用 AnimatedSwitcher 的 Shared Axis Z 轴转场，禁止在 transitionBuilder 内二次包 Curve。
- Dock 延迟 80ms 从 0.25 偏移上浮，隐藏 Tab 在淡出结束后 Offstage。

## 后果

- 首页首屏纵向空间减少约 28%，快捷记工不需要打开编辑器。
- 单条坏记录不再导致整库只读；用户能看到丢弃数量并恢复备份。
- 启动页、欢迎页和首页的深浅色材质连续；低端设备可退回普通磨砂。
- 普通编辑的磁盘写入延迟最多 300ms；应用退到后台或销毁前必须 flush。

## 不变量

- 包名 `com.myhours.app`、存储文件 `my-hours.json`、备份 `app: my-hours`、版本 4 契约不变。
- 字体族不变；数字继续使用 tabular figures。
- 不引入 GPL 代码或资源。
